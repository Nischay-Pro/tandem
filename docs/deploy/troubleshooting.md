# Troubleshooting the Tandem server

Use this page when the app cannot reach Tandem or the API is not ready. These
checks do not delete the phone's cached budget or queued changes.

| What you see                                            | Check                                                                                                                                                                                                   | What to do                                                                                                                                                         |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The app says Tandem is not responding                   | From a device on the same network, open the Tandem URL and check that `/api/v1/health/ready` responds.                                                                                                  | Use the public Tandem address, including the `/api/v1/` reverse-proxy route. Put that route before Actual's catch-all.                                             |
| The readiness check fails                               | Run `docker compose --env-file deploy/compose/.env -f deploy/compose/production.yml ps`, then inspect `docker compose --env-file deploy/compose/.env -f deploy/compose/production.yml logs tandem-api`. | Correct the reported configuration or storage problem, recreate the API, and check readiness again. Keep the Actual workspace volume while any write is uncertain. |
| Sign-in fails but Actual's website opens                | Confirm `ACTUAL_SERVER_URL` points to Actual at an address reachable from the API container. Check the installed Actual version against the [compatibility page](../concepts/actual-compatibility.md).  | Set the internal Actual service address in `.env`; use the public Tandem URL for `ACTUAL_PUBLIC_URL`, not for `ACTUAL_SERVER_URL`.                                 |
| OpenID sign-in does not return to Tandem                | Confirm `ACTUAL_PUBLIC_URL` is the HTTPS Tandem address and that the reverse proxy forwards `/api/v1/` to the API.                                                                                      | Correct the public URL or proxy route, restart the API, and try sign-in again. Password sign-in does not require `ACTUAL_PUBLIC_URL`.                              |
| Sign-in rate limiting treats many people as one address | Check the API logs and the immediate proxy address seen by the API.                                                                                                                                     | Set `TRUST_PROXY` to that proxy's IP or a narrow CIDR. Do not trust all forwarded headers or expose the API directly.                                              |
| Readiness reports `server_storage_full`                 | Check free space for the PostgreSQL volume and the Actual workspace volume.                                                                                                                             | Free space or expand the volume, then recheck `/api/v1/health/ready`. Do not delete the workspace volume to make room while writes may be uncertain.               |
| A secret-file setting cannot be read                    | Confirm the file exists at the path inside the container and is readable by the API's runtime user.                                                                                                     | Recreate the file with the documented owner and mode from the [start steps](install.md#start-the-service), then recreate the API.                                  |

When the service is healthy again, the phone can retry pending changes from
Sync. Do not clear app data to troubleshoot a server connection; that can
remove local-only changes.
